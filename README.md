# Tank Battle

A Battle City / Tank 1990 remake in **Godot 4.5** (GDScript, Forward+), extended
with an Isaac-style room-graph campaign, RPG progression, in-battle
structure building, and 2-player co-op (local or LAN).

All art is generated by headless Blender renders committed as PNGs; all sound is
synthesized at runtime. There are no audio files and no texture `ext_resource`
references in the scenes.

## Running

- **Engine**: Godot Engine 4.5 — `C:\Godot\tools\Godot_v4.5-stable_win64.exe`
- **Main scene**: `res://scenes/title_screen.tscn`

```powershell
$godot = "C:\Godot\tools\Godot_v4.5-stable_win64.exe"

& $godot --path .                       # play (starts at the title screen)
& $godot --path . scenes/main.tscn      # jump straight into a battle
```

> `godot` on PATH is a 4.7.1 Steam build. Use the explicit 4.5 path for anything
> that writes to the project.

## Game flow

`title_screen.tscn` → `main.tscn`. All modes (Campaign, Arcade, Daily Challenge)
go straight from the title into `main.tscn`; there is no separate map screen.

A campaign run is **12 acts, one Isaac-style floor each** — a floor is a graph of
8–11 rooms generated by `scripts/floor_map.gd`, and moving between rooms rebuilds
the battlefield in place rather than changing scene. Three visual themes
(Plains / Desert / Glacial) cycle across the acts, with difficulty scaling on
each repeat lap, on top of a player-chosen easy / normal / hard setting.

Progress is saved to `user://campaign_save.json`; the Daily Challenge keeps its
own seeded, single-life save in `user://daily_challenge_save.json`. Display and
audio settings (`settings.json`) and map-editor levels (`custom_maps.json`) are
separate `user://` files, deliberately outside the campaign save.

Two players can share one keyboard/pad locally, or play over LAN — see the 联机
sections in `CLAUDE.md`.

## Tests

There is no linter and no test framework. Verification is a set of `SceneTree`
scripts run headless — each prints `[FAIL]` lines and exits non-zero:

```powershell
& $godot --headless --path . --script tools/test_compile_all.gd       # loads every script/scene
& $godot --headless --path . --script tools/test_gameplay_runtime.gd  # boots a battle, checks wiring
python tools/qa_style_consistency.py                                  # sprite regression suite
```

The rest of `tools/test_*.gd` are feature-scoped; run the ones covering what you
touched. `qa_style_consistency.py` needs only numpy + Pillow, not Blender.

## Regenerating art

Sprites are Blender Cycles renders (Blender 5.2 LTS). The render pipeline lives
in `tools/sokpop_common.py`; the `tools/build_*.py` scripts contain only
modelling code.

```powershell
$blender = "C:\steam\steamapps\common\Blender\blender.exe"
& $blender --background --python tools/build_all_sokpop_assets_unified.py
```

**Do not run the unified script to change one asset** — it re-renders all 240
tank frames plus every tile, building and power-up. Use
`tools/rerender_tanks.py -- <name>` for tanks, or the narrower feature script
that owns the asset.

Several build scripts no longer reproduce the committed art, and running them
will silently restyle assets. Read the "Stale build scripts" section of
`CLAUDE.md` before re-rendering anything.

## 3D WebGL Clay Studio & Visual Inspection

You can inspect, explode, test physical animations, and compare Godot's 2D prerendered sprites + normal maps with native 3D PBR models in the interactive 3D WebGL Studio:

```powershell
python tools/launch_3d_clay_studio.py    # Launches Three.js 3D Studio on http://localhost:8080
```
